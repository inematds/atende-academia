## 📖 User guide

Landing page and step-by-step guide (PT/EN/ES): **https://inematds.github.io/atende-academia/guia/** · [English](https://inematds.github.io/atende-academia/guia/en/) · [Español](https://inematds.github.io/atende-academia/guia/es/)

Member support for a small gym or studio, in Python 3 using only the standard library (HTTP + SQLite): members and plans, group classes with booking and waitlist, check-in and reactivation, workout sheets, **animated exercise explanations**, physical assessment, conversation via web chat and WhatsApp (Evolution API), staff via Telegram, LGPD (Brazilian data protection law), and export to the Raio-X de Margem Recovery Panel.

**Status (10/19/2026): v0.11.0 — implementation complete; 99/99 tests, `LIMITES OK`. Telegram, the `/` and `/equipe` pages, Docker, and `tools/render-exercicios` delivered.** See "How to run in your environment".

## What the system does (v1)

- **Members and plans:** registration with a check-in code; monthly/quarterly/annual/drop-in class plans with price and validity period; enrollment with status `ativa`, `vencida`, `trancada`, `cancelada`; billing only as a **manual status** (`pago`/`pendente`) and a due-date notice.
- **Group classes:** weekly schedule (modality, instructor, room, spots); booking with a spot limit and advance notice; cancellation with a deadline; waitlist with automatic offer; automatic no-show (booking without check-in); last spot contested → one 201, the rest 409.
- **Check-in and attendance:** by code at the front desk or via chat ("I'm here"); a member with no check-in for N days receives a reactivation message (only with consent); attendance and monthly figures for the Raio-X.
- **Training:** the instructor builds the sheet with exercises from the library (sets, reps, load, rest); the member asks for "my workout for today"; every exercise in the catalog has an **SVG animation** (`/exercicios/<id>`) and, on WhatsApp, an MP4 generated by HyperFrames when available.
- **Physical assessment** scheduled with the instructor; the result is sensitive data (staff only, never via chat).
- **Conversation:** classes, book/cancel, my plan, my workout, explain exercise, FAQ, human attendant, health alert (192), "PARAR" (STOP).
- **Staff:** `/equipe` page with token and Telegram (`/aulas [date]`, `/fila`, `/responder`, `/encerrar`, booking and cancellation notices).
- **Campaigns** only with consent and a minimum advertising safeguard; **LGPD** (export, anonymize); **backup/restore**; **Docker** for VPS.

Full contract: `docs/ESPECIFICACAO.md` (22 sections). Out of scope for v1: section 16.

## How to run in your environment

The project is **planned, not implemented**: contract and tests are frozen, and an agent implements until the 99 tests pass. Anyone can run it in their own environment.

### Prerequisites

- Linux/macOS with `git`, `python3` ≥ 3.10, and `pytest` (`pip install pytest`; it is a development tool, the application does not depend on it).
- An agent via **subscription**: Codex CLI (`codex`) or Claude Code (`claude`). No API is called.
- For the final independent verification: `docker`; optionally a Chromium (Playwright or binary) for the SVG motion proof and Node 22 + HyperFrames + `ffprobe` to check the MP4 — without them the verifier prints `PULADO` for that step (never a silent "ok"). The verifier and `tools/render-exercicios` only use the already-installed HyperFrames (`npx --no-install hyperframes`); to install it once: `npm install hyperframes` at the repo root (`node_modules/`, `package.json`, and `package-lock.json` are in `.gitignore`, so `verificar-limites.sh` does not see them) or `npm install -g hyperframes`. Install it **after** the loop closes (before the independent verification): the agent does not need it and must not download packages.
- Long-run method and tools: clone of `~/projetos/execucao-longa` (`tools/loop-longrun.sh`, `docs/PLANO-EXECUCAO-LONGA.md`). If you don't have it, the interactive `/goal` route (below) doesn't need it.

### 1. Answer the decisions and freeze the contract

```sh
cd atende-academia
# read docs/DECISOES-ABERTAS.md; "ok on everything" = nothing to change
python3 -m pytest -q --collect-only | tail -n 1     # 99 tests collected
bash longrun/2026-10-05-academia-v1/congelar.sh     # writes hash-congelado.txt and makes 1 commit
```

If you change anything marked ⚠ in the decisions, edit `docs/ESPECIFICACAO.md` and the tests **before** freezing. Once frozen, the contract, the tests, and the two verifiers are protected: the agent does not alter them; if a test contradicts the spec, it logs it in `failures.md` and stops (human gate).

### 2a. Headless loop (Codex `gpt-6-astra`)

```sh
~/projetos/execucao-longa/tools/loop-longrun.sh longrun/2026-10-05-academia-v1
```

Configuration in `longrun/2026-10-05-academia-v1/loop.env` (quick/final test, protected files, 20 cycles × 30 min, 8 GB, stop after 3 cycles without progress, `CODEX_ARGS` allowing a local socket in the sandbox). The loop uses `flock`, `timeout`, and `MemoryMax`, reverts any cycle that touches a protected file, commits a checkpoint per cycle, and stops by itself when the final test passes.

### 2b. `/goal` in the Codex TUI

```sh
cd atende-academia && codex -c sandbox_workspace_write.network_access=true
```

Paste `longrun/2026-10-05-academia-v1/prompt-goal-codex.md` in full (it starts with `/goal`). Track progress with `/goals`; `/goal pause|resume`.

### 2c. `/goal` in Claude Code

A **new** Claude Code session opened in the project folder; follow `longrun/2026-10-05-academia-v1/prompt-goal-claude.md` (the `/goal` condition + the block from `prompt-goal-codex.md` as the first message).

### 3. Monitor

```sh
tail -n 20 longrun/2026-10-05-academia-v1/loop.log        # headless
cat longrun/2026-10-05-academia-v1/state.md               # Works / Missing / How to resume
tail -n 5 longrun/2026-10-05-academia-v1/progress.md
python3 -m pytest -q tests/ | tail -n 3
```

Done = `python3 -m pytest -q tests/` → **99 passed** and `bash longrun/2026-10-05-academia-v1/verificar-limites.sh` → **LIMITES OK** (contract hash intact, same number of tests, only in-scope files, no external dependency, no external URL in the code, no key, no `0.0.0.0` in the code, no MP4/`node_modules` committed).

### 4. Independent verification (level 4, human)

```sh
python3 longrun/2026-10-05-academia-v1/verificar-independente.py   # INDEPENDENTE OK
```

It looks for fixture values copied into the code; brings up a **never-before-seen** gym (different schedule, plans, deadlines, holiday, clock) and checks rules that only pass if the logic is general; opens 3 SVGs in a headless Chromium and requires that two frames at different instants be different (motion proof; without a Chromium that passes calibration → `PULADO`); if HyperFrames is installed, renders an exercise with `tools/render-exercicios` and checks 720×720, ~4 s, no audio with `ffprobe` (otherwise → `PULADO`); runs `docker build` and tests the container healthcheck (without `docker` → `PULADO`). The last line reads `INDEPENDENTE OK (movimento: ..., hyperframes: ..., docker: ...)` so you can see what was actually checked. Then open `/`, `/equipe`, and `/exercicios/prancha` in the browser.

## Run (after implementation)

```sh
mkdir -p dados && cp exemplos/academia.json dados/academia.json   # edit name, token, schedule, plans
./atende serve --porta 8080 --dados dados
./atende raiox --dados dados --mes 2026-10 --acompanhamento acompanhamento.json
./atende backup --dados dados --saida backups/academia.zip
```

Member chat at `/`, staff at `/equipe` (token from `academia.json` in the `X-Token` header), animation of each exercise at `/exercicios/<id>`. `PUBLIC_URL` (public address, HTTPS, no trailing slash) goes into the links sent to the member; without it the links are relative.

**Exercise MP4s (WhatsApp does not display SVG):** `tools/render-exercicios [--ids a,b] [--saida DIR]` generates `web/exercicios/<id>.mp4` (720×720, 4 s looping, no audio) from each SVG with HyperFrames — local render via Chromium, no API or account. It requires Node 22+, HyperFrames installed (`npm install hyperframes` at the root; the script downloads nothing by itself), and `ffprobe`. The composition is **CSS only** (the inline SVG inside `data-width="720" data-height="720" data-duration="4"`, no GSAP or CDN): the render fetches each frame through the CSS/WAAPI adapters, which is why the SVGs use `@keyframes` with durations of 1, 2, or 4 s and never SMIL. It is a build step: it runs once on the publisher's machine, not on the server or in the tests. With the MP4 present and `PUBLIC_URL` set, the bot sends the video via `sendMedia`; otherwise it sends the page link.

## VPS deployment

This is the owner's step, with their credentials and their machine (the system never does this on its own).

1. **Bring up the compose.** On the VPS, with Docker: clone the repo, `cp .env.exemplo .env`, fill in the variables, and run `docker compose up -d --build`. The `atende` service listens only on `127.0.0.1:8080`, stores everything in `./dados` (volume `/dados`), and has a healthcheck at `/api/saude`. On the first start, `dados/academia.json` is copied from the example: edit name, **token**, schedule, and plans and restart (`docker compose restart`).
2. **HTTPS proxy.** Put a reverse proxy (Caddy, Nginx, or Traefik) with a certificate in front of `127.0.0.1:8080`, on the gym's domain. Never expose port 8080 directly.
3. **`PUBLIC_URL`.** In `.env`, `PUBLIC_URL` = the domain's HTTPS address, no trailing slash. This is what goes into the exercise links and the MP4 `sendMedia`.
4. **Evolution webhook.** Fill in `EVOLUTION_URL` (Evolution's internal address), `EVOLUTION_API_KEY`, `EVOLUTION_INSTANCIA`, and a long, random `WEBHOOK_SEGREDO`. In the Evolution panel, point the instance webhook to `<PUBLIC_URL>/webhook/evolution/<WEBHOOK_SEGREDO>` with the `MESSAGES_UPSERT` event. A wrong secret returns 404.
5. **Telegram webhook.** Create the bot with BotFather, add it to the staff group, and fill in `TELEGRAM_API_URL` (Telegram API address), `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID` (group id), and `TELEGRAM_SEGREDO`. Register the webhook by calling the bot API's `setWebhook` with `url=<PUBLIC_URL>/webhook/telegram` and `secret_token=<TELEGRAM_SEGREDO>` — the system rejects (401) updates without that header and ignores other chats. In the group: reply to the `#id` message, `/responder <id> <text>`, `/encerrar <id>`, `/fila`, `/aulas [YYYY-MM-DD]`.
6. **Generate the MP4s.** On a machine with Node 22+, `npm install hyperframes`, and `ffprobe`, run `tools/render-exercicios` (or `--ids prancha,agachamento --saida DIR`) and copy the `.mp4` files to the folder pointed to by `EXERCICIOS_MP4_DIR` (e.g. `/dados/mp4` inside the container = `./dados/mp4` on the VPS). Without MP4s, WhatsApp receives the link to the animated page.
7. **Daily backup.** In the host's cron, for example at 3 a.m.: `docker compose exec -T atende ./atende backup --dados /dados --saida /dados/backups/academia-$(date +\%F).zip` (`./atende backup` can run with the server on). To restore: stop the service, run `./atende restaurar --dados /dados --entrada <file>`, and start it again. Keep copies off the VPS.
