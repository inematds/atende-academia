## 📖 User guide

Landing page and step-by-step guide: **https://inematds.github.io/atende-academia/guia/en/** · [Português](https://inematds.github.io/atende-academia/guia/) · [Español](https://inematds.github.io/atende-academia/guia/es/)

Customer service for a small gym or studio, in Python 3 with the standard library only (HTTP + SQLite): members and plans, group classes with booking and a waitlist, check-in and win-back, workout card, **animated exercise explanations**, physical assessment, web chat and WhatsApp conversation (Evolution API), staff desk on Telegram, LGPD and export to the Recovery Panel of Raio-X de Margem. The chat and the data are in Portuguese in v1; LGPD (Brazil's data protection law) and `192` (the Brazilian ambulance number) are Brazil's.

**Status (2026-10-05): planned: contract, 99 tests and a long-run folder are ready; implementation pending.** See "How to run in your own environment".

## What the system does (v1)

- **Members and plans:** registration with a check-in code; monthly/quarterly/annual/drop-in class plans with price and validity; enrollment with status `ativa`, `vencida`, `trancada`, `cancelada` (active, expired, frozen, canceled); billing only as a **manual status** (`pago`/`pendente`, paid or pending) and an expiry notice.
- **Group classes:** weekly grid (modality, instructor, room, spots); booking with a spot cap and lead time; cancellation with a deadline; waitlist with an automatic offer; automatic no-show (booking without check-in); last spot contested → one 201, the rest 409.
- **Check-in and attendance:** by code at the front desk or through the chat ("cheguei", "I'm here"); a member with no check-in for N days gets a win-back message (only with consent); attendance and monthly numbers for Raio-X.
- **Workouts:** the instructor builds the card from the exercise library (sets, reps, load, rest); the member asks for "meu treino de hoje" (my workout today); every catalog exercise has an **SVG animation** (`/exercicios/<id>`) and, on WhatsApp, an MP4 generated by HyperFrames when it exists.
- **Physical assessment** booked with the instructor; the result is sensitive data (staff only, never through the chat).
- **Chat:** classes, book/cancel, my plan, my workout, explain an exercise, FAQ, human agent, health alert (192), "PARAR" (stop).
- **Staff:** `/equipe` page with a token and Telegram (`/aulas [date]`, `/fila`, `/responder`, `/encerrar`, booking and cancellation notices).
- **Campaigns** only with consent and a minimal advertising guardrail; **LGPD** (export, anonymize); **backup/restore**; **Docker** for a VPS.

Full contract: `docs/ESPECIFICACAO.md` (22 sections). Out of v1: section 16.

## How to run in your own environment

The project is **planned, not implemented**: contract and tests frozen, an agent implements until the 99 tests pass. Anyone can run it in their own environment.

### Prerequisites

- Linux/macOS with `git`, `python3` ≥ 3.10 and `pytest` (`pip install pytest`; it is a development tool, the application does not depend on it).
- An agent through your **subscription**: Codex CLI (`codex`) or Claude Code (`claude`). No API is called.
- For the final independent verification: `docker`; optionally a Chromium (Playwright or a binary) for the SVG motion proof and Node 22 + HyperFrames + `ffprobe` to check the MP4. Without them the verifier prints `PULADO` (skipped) for that stage (never a silent "ok"). The verifier and `tools/render-exercicios` only use the HyperFrames that is already installed (`npx --no-install hyperframes`); to install it once: `npm install hyperframes` at the repo root (`node_modules/`, `package.json` and `package-lock.json` are in `.gitignore`, so `verificar-limites.sh` does not see them) or `npm install -g hyperframes`. Install it **after** the loop closes (before the independent verification): the agent does not need it and must not download packages.
- Long-run method and tools: a clone of `~/projetos/execucao-longa` (`tools/loop-longrun.sh`, `docs/PLANO-EXECUCAO-LONGA.md`). If you do not have it, the interactive `/goal` route (below) does not need it.

### 1. Answer the decisions and freeze the contract

```sh
cd atende-academia
# read docs/DECISOES-ABERTAS.md; "ok on everything" = nothing to change
python3 -m pytest -q --collect-only | tail -n 1     # 99 tests collected
bash longrun/2026-10-05-academia-v1/congelar.sh     # writes hash-congelado.txt and makes 1 commit
```

If you change anything marked ⚠ in the decisions, edit `docs/ESPECIFICACAO.md` and the tests **before** freezing. Once frozen, the contract, the tests and the two verifiers are protected: the agent does not change them; if a test contradicts the spec, it logs it in `failures.md` and stops (human gate).

### 2a. Headless loop (Codex `gpt-6-astra`)

```sh
~/projetos/execucao-longa/tools/loop-longrun.sh longrun/2026-10-05-academia-v1
```

Configuration in `longrun/2026-10-05-academia-v1/loop.env` (fast/final test, protected files, 20 cycles × 30 min, 8 GB, stop after 3 cycles with no progress, `CODEX_ARGS` allowing a local socket in the sandbox). The loop does `flock`, `timeout`, `MemoryMax`, reverts a cycle that touches a protected file, commits a checkpoint per cycle and stops by itself when the final test passes.

### 2b. `/goal` in the Codex TUI

```sh
cd atende-academia && codex -c sandbox_workspace_write.network_access=true
```

Paste the whole of `longrun/2026-10-05-academia-v1/prompt-goal-codex.md` (it starts with `/goal`). Follow with `/goals`; `/goal pause|resume`.

### 2c. `/goal` in Claude Code

A **new** Claude Code session opened in the project folder; follow `longrun/2026-10-05-academia-v1/prompt-goal-claude.md` (the `/goal` condition + the block from `prompt-goal-codex.md` as the first message).

### 3. Follow along

```sh
tail -n 20 longrun/2026-10-05-academia-v1/loop.log        # headless
cat longrun/2026-10-05-academia-v1/state.md               # Works / Missing / How to resume
tail -n 5 longrun/2026-10-05-academia-v1/progress.md
python3 -m pytest -q tests/ | tail -n 3
```

Done = `python3 -m pytest -q tests/` → **99 passed** and `bash longrun/2026-10-05-academia-v1/verificar-limites.sh` → **LIMITES OK** (contract hash intact, same number of tests, only in-scope files, no external dependency, no external URL in the code, no key, no `0.0.0.0` in the code, no MP4 or `node_modules` committed).

### 4. Independent verification (level 4, human)

```sh
python3 longrun/2026-10-05-academia-v1/verificar-independente.py   # INDEPENDENTE OK
```

It looks for fixture values copied into the code; brings up a gym **never seen before** (another grid, plans, deadlines, holiday, clock) and checks rules that only pass if the logic is general; opens 3 SVGs in a headless Chromium and requires two frames at different instants to differ (motion proof; with no Chromium that passes calibration → `PULADO`); if HyperFrames is installed, renders one exercise with `tools/render-exercicios` and checks 720×720, ~4 s, no audio with `ffprobe` (otherwise → `PULADO`); runs `docker build` and tests the container healthcheck (without `docker` → `PULADO`). The last line says `INDEPENDENTE OK (movimento: ..., hyperframes: ..., docker: ...)` so you can see what was actually checked. Then open `/`, `/equipe` and `/exercicios/prancha` in the browser.

## Run (once implemented)

```sh
mkdir -p dados && cp exemplos/academia.json dados/academia.json   # edit name, token, grid, plans
./atende serve --porta 8080 --dados dados
./atende raiox --dados dados --mes 2026-10 --acompanhamento acompanhamento.json
./atende backup --dados dados --saida backups/academia.zip
```

Member chat at `/`, staff at `/equipe` (token from `academia.json` in the `X-Token` header), animation of each exercise at `/exercicios/<id>`. `PUBLIC_URL` (public address, HTTPS, no trailing slash) goes into the links sent to the member; without it the links are relative.

**Exercise MP4s (WhatsApp does not show SVG):** `tools/render-exercicios [--ids a,b] [--saida DIR]` produces `web/exercicios/<id>.mp4` (720×720, 4 s loop, no audio) from each SVG with HyperFrames: a local render by Chromium, no API and no account. It needs Node 22+, HyperFrames installed (`npm install hyperframes` at the root; the script downloads nothing by itself) and `ffprobe`. The composition is **CSS only** (the inline SVG inside `data-width="720" data-height="720" data-duration="4"`, no GSAP and no CDN): the render fetches each frame through the CSS/WAAPI adapters, which is why the SVGs use `@keyframes` with durations of 1, 2 or 4 s and never SMIL. It is a build step: it runs once on the publisher's machine, not on the server or in the tests. With the MP4 present and `PUBLIC_URL` set, the bot sends the video through `sendMedia`; otherwise it sends the page link.

## Files

- `docs/ESPECIFICACAO.md`: the contract (22 sections, route table, rules with boundaries, out of v1).
- `docs/DECISOES-ABERTAS.md`: decisions with a default proposal; questions for the owner.
- `docs/MAPA-RAIO-X.md`: each leak of the `servicos` package → a v1 piece or the reason it stays out.
- `tests/`: 99 black-box tests (`conftest.py` brings up the CLI, a fixed clock, a fake Evolution/Telegram server, a temporary MP4 folder). Fixture in `tests/fixtures/academia.json`; copy in `exemplos/`.
- `longrun/2026-10-05-academia-v1/`: goal (level 3+), plan, state, loop.env, prompts, `congelar.sh`, `verificar-limites.sh`, `verificar-independente.py`.
- `FALHAS.md`: one line per failure (date, what broke, smallest fix, prompt | infra).
