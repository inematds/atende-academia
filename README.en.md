## 📖 Usage guide

Landing page and step-by-step guide (PT/EN/ES): **https://inematds.github.io/atende-academia/guia/** · [English](https://inematds.github.io/atende-academia/guia/en/) · [Español](https://inematds.github.io/atende-academia/guia/es/)

Member service for a small gym or studio, in Python 3 using only the standard library (HTTP + SQLite): members and plans, group classes with booking and waitlist, check-in and reactivation, workout sheets, **animated exercise explanations**, physical assessment, conversation through web chat and WhatsApp (Evolution API), staff via Telegram, LGPD (Brazilian data protection law) and export to the Recovery Panel of Raio-X de Margem.

**Status (10/19/2026): v0.11.0 — implementation complete; 99/99 tests, `LIMITES OK`. Telegram, the `/` and `/equipe` pages, Docker and `tools/render-exercicios` delivered.** See "How to run in your environment".

## What the system does (v1)

- **Members and plans:** registration with a check-in code; monthly/quarterly/annual/single-class plans with price and validity; enrollment with status `ativa`, `vencida`, `trancada`, `cancelada`; billing only as a **manual status** (`pago`/`pendente`) and a due-date notice.
- **Group classes:** weekly schedule (modality, instructor, room, spots); booking with a spot limit and advance notice; cancellation with a deadline; waitlist with automatic offer; automatic no-show (booking without check-in); last spot contested → one 201, the rest 409.
- **Check-in and attendance:** by code at the front desk or through the chat ("I'm here"); a member with no check-in for N days receives reactivation (only with consent); attendance and monthly numbers for Raio-X.
- **Workouts:** the instructor builds the sheet from library exercises (sets, reps, load, rest); the member asks "my workout for today"; any exercise in the catalog has an **SVG animation** (`/exercicios/<id>`) and, on WhatsApp, an MP4 generated by HyperFrames when available.
- **Physical assessment** scheduled with the instructor; the result is sensitive data (staff only, never through the chat).
- **Conversation:** classes, book/cancel, my plan, my workout, explain exercise, FAQ, human attendant, health alert (192), "PARAR" (stop).
- **Staff:** `/equipe` page with token and Telegram (`/aulas [date]`, `/fila`, `/responder`, `/encerrar`, booking and cancellation notices).
- **Campaigns** only with consent and a minimum advertising safeguard; **LGPD** (export, anonymize); **backup/restore**; **Docker** for VPS.

Full contract: `docs/ESPECIFICACAO.md` (22 sections). Out of v1: section 16.

## How to run in your environment

The system is **implemented**: v0.11.0, 99/99 tests, `LIMITES OK` and independent verification passed. Anyone can run it in their own environment.

### Prerequisites

- Linux/macOS with `git` and `python3` ≥ 3.10. The application has no dependencies; `pytest` (`pip install pytest`) is only needed to check the tests.
- For deployment: `docker` (with `docker compose`).
- Optional, for the exercise MP4s: Node 22 + HyperFrames + `ffprobe`. `tools/render-exercicios` and the verifier only use the HyperFrames already installed (`npx --no-install hyperframes`); to install it once: `npm install hyperframes` in the repo root (`node_modules/`, `package.json` and `package-lock.json` are in `.gitignore`, so `verificar-limites.sh` does not see them) or `npm install -g hyperframes`.

### 1. Clone and check

```sh
git clone https://github.com/inematds/atende-academia && cd atende-academia
python3 -m pytest -q tests/ | tail -n 1                          # 99 passed
bash longrun/2026-10-05-academia-v1/verificar-limites.sh          # LIMITES OK at close; now flags only guia/ and README.en/es (docs added later)
```

`LIMITES OK` = contract hash intact, same number of tests, only files within scope, no external dependency, no external URL in the code, no key, no `0.0.0.0` in the code, no MP4/`node_modules` committed.

### 2. Run

```sh
mkdir -p dados && cp exemplos/academia.json dados/academia.json   # edit name, token, schedule, plans
./atende serve --porta 8080 --dados dados
./atende raiox --dados dados --mes 2026-10 --acompanhamento acompanhamento.json
./atende backup --dados dados --saida backups/academia.zip
```

Member chat at `/`, staff at `/equipe` (token from `academia.json` in the `X-Token` header), animation of each exercise at `/exercicios/<id>`. `PUBLIC_URL` (public address, HTTPS, no trailing slash) goes into the links sent to the member; without it the links are relative. Without the Evolution and Telegram variables, the outbox is simulated and no network call goes out. The 20 default decisions are in `docs/DECISOES-ABERTAS.md`.

**Exercise MP4s (WhatsApp does not show SVG):** `tools/render-exercicios [--ids a,b] [--saida DIR]` generates `web/exercicios/<id>.mp4` (720×720, 4 s loop, no audio) from each SVG with HyperFrames — local render via Chromium, no API or account. Requires Node 22+, HyperFrames installed (`npm install hyperframes` in the root; the script does not download anything on its own) and `ffprobe`. The composition is **CSS only** (the inline SVG inside `data-width="720" data-height="720" data-duration="4"`, no GSAP or CDN): the render fetches each frame through the CSS/WAAPI adapters, which is why the SVGs use `@keyframes` with durations of 1, 2 or 4 s and never SMIL. It is a build step: it runs once on the publisher's machine, not on the server or in the tests. **This render has not been run yet** (the SVG animations work on the web). With the MP4 present and `PUBLIC_URL` set, the bot sends the video via `sendMedia`; otherwise it sends the page link.

### 3. Independent verification (level 4)

```sh
python3 longrun/2026-10-05-academia-v1/verificar-independente.py   # INDEPENDENTE OK
```

It looks for fixture values copied into the code; spins up a **never-before-seen** gym (different schedule, plans, deadlines, holiday, clock) and checks rules that only pass if the logic is general; opens 3 SVGs in a headless Chromium and requires two frames at different instants to differ (proof of motion; without a Chromium that passes calibration → `PULADO`); if HyperFrames is installed, renders an exercise with `tools/render-exercicios` and checks 720×720, ~4 s, no audio with `ffprobe` (otherwise → `PULADO`); runs `docker build` and tests the container healthcheck (without `docker` → `PULADO`). At delivery it returned `INDEPENDENTE OK (movimento: chromium, hyperframes: pulado, docker: ok)`. Then open `/`, `/equipe` and `/exercicios/prancha` in the browser.

### 4. How it was built (to redo or adapt)

The system was built using the long-run execution method (`~/projetos/execucao-longa`: `tools/loop-longrun.sh`, `docs/PLANO-EXECUCAO-LONGA.md`), by an agent through the **subscription** (Codex CLI and Claude Code, no API called):

1. The decisions in `docs/DECISOES-ABERTAS.md` were answered and the contract was frozen with `bash longrun/2026-10-05-academia-v1/congelar.sh` (writes `hash-congelado.txt`). The contract, tests and the two verifiers were protected: the agent did not alter them; a test in conflict with the spec went to `failures.md` (human gate).
2. The agent worked in a headless loop (`~/projetos/execucao-longa/tools/loop-longrun.sh longrun/2026-10-05-academia-v1`, Codex `gpt-6-astra`, configuration in `loop.env`: 20 cycles × 30 min, 8 GB, stop after 3 cycles without progress, `flock`, `timeout`, `MemoryMax`, rollback of any cycle that touched a protected file, checkpoint per cycle) and was completed by Claude Code, up to **99 passed** and **LIMITES OK**.
3. The tracking stayed in `longrun/2026-10-05-academia-v1/` (`loop.log`, `state.md`, `progress.md`).

Want to change a rule marked ⚠ or take the template to another business? Edit `docs/ESPECIFICACAO.md` and the tests, freeze again and run the headless loop, or `/goal` in the Codex TUI (`codex -c sandbox_workspace_write.network_access=true` + `longrun/2026-10-05-academia-v1/prompt-goal-codex.md`) or in Claude Code (`longrun/2026-10-05-academia-v1/prompt-goal-claude.md`).

## VPS deployment

A step for the owner, with their own credentials and machine (the system never does this on its own).

1. **Bring up the compose.** On the VPS, with Docker: clone the repo, `cp .env.exemplo .env`, fill in the variables and run `docker compose up -d --build`. The `atende` service listens only on `127.0.0.1:8080`, stores everything in `./dados` (volume `/dados`) and has a healthcheck at `/api/saude`. On first start, `dados/academia.json` is copied from the example: edit name, **token**, schedule and plans and restart (`docker compose restart`).
2. **HTTPS proxy.** Put a reverse proxy (Caddy, Nginx or Traefik) with a certificate in front of `127.0.0.1:8080`, on the gym's domain. Never expose port 8080 directly.
3. **`PUBLIC_URL`.** In `.env`, `PUBLIC_URL` = the domain's HTTPS address, no trailing slash. This is what goes into the exercise links and the MP4 `sendMedia`.
4. **Evolution webhook.** Fill in `EVOLUTION_URL` (Evolution's internal address), `EVOLUTION_API_KEY`, `EVOLUTION_INSTANCIA` and a long, random `WEBHOOK_SEGREDO`. In the Evolution panel, point the instance webhook to `<PUBLIC_URL>/webhook/evolution/<WEBHOOK_SEGREDO>` with the `MESSAGES_UPSERT` event. A wrong secret returns 404.
5. **Telegram webhook.** Create the bot with BotFather, add it to the staff group and fill in `TELEGRAM_API_URL` (Telegram API address), `TELEGRAM_TOKEN`, `TELEGRAM_CHAT_ID` (group id) and `TELEGRAM_SEGREDO`. Register the webhook by calling the bot API's `setWebhook` with `url=<PUBLIC_URL>/webhook/telegram` and `secret_token=<TELEGRAM_SEGREDO>` — the system rejects (401) an update without that header and ignores other chats. In the group: reply on top of the `#id` message, `/responder <id> <text>`, `/encerrar <id>`, `/fila`, `/aulas [YYYY-MM-DD]`.
6. **Generate the MP4s.** On a machine with Node 22+, `npm install hyperframes` and `ffprobe`, run `tools/render-exercicios` (or `--ids prancha,agachamento --saida DIR`) and copy the `.mp4` files to the folder pointed to by `EXERCICIOS_MP4_DIR` (e.g. `/dados/mp4` inside the container = `./dados/mp4` on the VPS). Without MP4s, WhatsApp receives the animated page link.
7. **Daily backup.** In the host's cron, for example at 3 a.m.: `docker compose exec -T atende ./atende backup --dados /dados --saida /dados/backups/academia-$(date +\%F).zip` (`./atende backup` can run with the server on). To restore: stop the service, run `./atende restaurar --dados /dados --entrada <file>` and start it again. Keep copies outside the VPS.
